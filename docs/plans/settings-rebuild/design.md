# Settings rebuild — design

Visual reference: Resume / Copilot workspaces (vertical `Tabs` side-nav + bordered `ScrollArea` content, `Group`/`Row` kit, `ToggleSwitch`, `SegTabs`, `status-line`, brand teal accent). Static prototype in `prototype/` (`settings.html?theme=dark|light#<page>`), screenshots in `prototype/shots/`.

## 1. Information architecture

One screen, `settings`, with a 212 px side-nav (grouped, with status dots) and a search box on top (⌘F inside Settings, or `/`). 12 pages in 5 groups:

| Group | Page id | Contents |
|---|---|---|
| **Basics** | `general` | career-ops folder (+install), appearance (theme), language, refresh cadence, updates (on/off, check now) |
| **AI** | `runners` | 6 runner cards: readiness badge, active toggle, "what it may do", model + helper model, per-runner fix hints |
| | `keys` | **Key manager**: OpenRouter, OpenCode Zen, Firecrawl, plugin keys (read-only presence). Masked tail, add/replace/remove, Test, last tested, "used by" |
| | `local-models` | Pre-screen model (verdict-small) install/size/status/uninstall-less; Copilot STT engines status; memory check |
| **Connections** | `integrations` | Category chips (Services, Browser login, Skills, Plugins) → rows with status pill, Connect/Test/Disconnect, detail drawer with checks + config; the existing `components/integrations/*` reused |
| **Workflows** | `jobs` | Pre-screen policy (countries, remote-anywhere, min years), pipeline limits (read-only: sequential eval, scan caps), board defaults pointer |
| | `resume` | Doc defaults (tone, length, humanize), page format, template chip (read-only), ATS local-model status |
| | `agent` | Active runner chip, permission table (read-only), skills in use, default entrypoints |
| | `copilot` | STT (engine, model, device, end-silence, vocab), answer engine (tier, models, OpenRouter privacy, fact-check, vision, auto-answer), retention + redact + Privacy mode; link → Copilot workspace |
| | `monitoring` | Refresh cadence summary, run-log retention, "what raises findings" list (read-only) |
| **System** | `data` | Data locations (open in Finder), secrets overview (names + status only), export consents, clear run logs / chats / copilot sessions (danger zone) |
| | `advanced` | Diagnostics (runner PATH, node, python, memory), recheck readiness, log tail, limits table, reset settings (keeps keys), reset everything (danger) |

**Deep links:** `navigate('settings', { page?: PageId, focus?: string })`. `focus` = control id (`key:openrouter`, `runner:codex`, `integration:firecrawl`, `prescreen`); the page scrolls to it and pulses it for 1.2 s. `careerloom:navigate` detail becomes `{section, id?, page?, focus?}`; `lib/nav.ts` gets `goToSettings(page, focus?)` and `goToIntegrations()` becomes an alias to `goToSettings('integrations')`. `careerloom.section` values `integrations` map to `settings`. Hash-free; last page persisted in `careerloom.settingsPage` (STAY localStorage).

**Attention dots** on the side-nav (and on the sidebar Settings item) = `needs attention`: no ready runner, missing key for the active runner, Firecrawl/browser errored, local model absent while pre-screen is used.

**Search:** a static registry `settings-registry.ts` of `{page, focus, label, keywords[]}` (≈70 entries, generated by hand, unit-tested to point at existing ids). `cmdk` (`components/ui/command`) popover under the search field; Enter jumps + focuses; also exposed in the ⌘K palette as "Settings: <label>".

## 2. What moves, what stays (rule)

*Single source of truth*: every persisted value has exactly one editor in Settings, **except** per-record data (boards, a document's template, a job's status) and per-session/live tuning (Copilot coaching/overlay/hotkeys/audio, because they are tuned against a live preview). Other screens show a read-only `SettingChip` (`Runner: Claude Code · Ready`) with "Manage in Settings" (`goToSettings(page, focus)`).

Screens changing: Agent (runner chip), Jobs (prescreen popover → summary + link, keeps Retrain/feedback), Copilot workspace (Engine/Transcription/Privacy tabs removed → "Configuration" strip with chips + links; Setup/Practice/Audio/Coaching/Overlay/Hotkeys/Sessions stay), Onboarding (reuses the same `KeyField`, `RunnerPicker`, `LocalModelSetup`), Integrations screen (deleted; ⌘7 → Settings › Integrations), Resume Ats copy → link.

## 3. Key manager (API keys page)

Row per provider (`keys-registry` in main, so adding a provider = one entry):

```
[icon] OpenRouter            ● Saved  ••••a1b2          last tested 2m ago · 412 ms · ok
       Used by: API runner · Copilot answers             [Test] [Replace] [Remove]
```
- States: *Not set* (empty input + "Get a key" link), *Saved* (masked tail only), *Replacing* (inline input, live format validation, Save/Cancel), *Testing* (spinner), *Test failed* (error text with reason: invalid key / network / quota / unreachable; never echoes the key), *Keychain unavailable* (blocking notice, inputs disabled).
- **Never** shows a secret: the renderer only receives `{id, label, hasKey, tail, usedBy[], lastTest}` where `tail` is the last 4 characters computed in main. Pasted values go renderer → main once over `keysSet` and are cleared from state immediately.
- **Test connection** (cheapest, no tokens): OpenRouter `GET /api/v1/auth/key` (returns label/usage/limit, free); Zen `GET /zen/v1/models` (list, free); Firecrawl: existing loopback `/` health + auth probe. 8 s timeout, one in-flight per provider, result `{ok, latencyMs, detail, at}` persisted in settings.json `keyMeta[id]` (non-secret). Tests use fake local servers (base URL injectable in tests only).
- Remove → confirm dialog showing what stops working ("API runner and Copilot answers will stop"). Undo toast is not possible for deletion (the secret is gone) — the dialog replaces it.
- Plugin keys: read-only list "Set / Missing" per plugin with link to the plugin row (Integrations); never read back.

## 4. Interaction design

- **Save model:** toggles, selects, segmented controls apply instantly (optimistic) with an **undo toast** (5 s, "Refresh set to 5 min · Undo") — undo reapplies the previous value through the same setter. Text/number/path/secret fields are **draft-with-validate**: inline validation as you type, Save button appears when dirty (`Unsaved` chip in the group header, Esc/"Revert"), Enter saves, blur does not.
- **Per-group state chip** in each `Group` header: `Saved` (fades after 2 s), `Unsaved`, `Saving…`, `Error — retry`. Page header shows nothing global (no global save bar → no ambiguity).
- **Validation:** shared schema in `electron/settings/schema.ts` mirrored by renderer pure validators (same module imported by both — it has no electron imports). Main re-validates; failures return `{field, message}` shown under the control.
- **Readiness badges:** one `ReadinessBadge` (`ready | needs-setup | error | off | checking`) used by runners, integrations, local models; same colours as `StatusPill`.
- **Connection tests:** button → inline spinner → result line (`ok · 412 ms` / reason). Disabled while running; result persists with timestamp ("tested 2m ago", relative, updates).
- **Empty / first-run:** keys page with nothing set shows the three providers collapsed to "Add" cards plus a one-line "Which do I need?" (runner-dependent: shows the keys the *active runner* needs first, marked "Needed for your active runner").
- **Danger zone:** a bordered, collapsed-by-default group at the bottom of Data & Advanced; every action opens `AlertDialog` that names the consequence and the item counts; destructive button requires typing the word for "Reset everything".
- **Keyboard / a11y:** side-nav is a roving-tab `role=tablist` (arrow keys, Home/End); `Tabs` from shadcn already provides it. Search `role=combobox`. Every control has a visible label + `aria-describedby` hint; status is text + icon (not colour only); toasts `role=status`; focus pulse respects reduced motion; all pages operable at 900×600 min window (nav collapses to icon-less compact 168 px).
- **Light/dark:** only token vars from `careerloom.css`; verified in both.

## 5. Contract (additive, migration-safe)

- `settings.json` gains optional `prefs: { refreshMs?, locale?, updates?: {enabled}, retention?: {runLogDays}, docs?: {tone,length,humanize}, nav?: ... }` and `keyMeta: Record<keyId,{testedAt,ok,latencyMs,detail?}>`. `readSettings` fills defaults for missing keys; unknown keys preserved on write; writes become atomic (tmp + rename) with one `settings.json.bak`. Old files (root/runner/models/helperModels only) load unchanged; downgrade-safe because old code ignores unknown keys (it re-serialises only the 4 known ones → prefs lost on downgrade, acceptable and documented).
- New IPC (all return envelopes as today): `keysList()`, `keysSet(id, value|null)`, `keysTest(id)`, `prefsGet()/prefsSet(patch)`, `browserRevoke(domain)`, `retentionPrune()`, `dataLocations()`, `settingsReset(scope)`. Existing `setApiKey`/`getSettings.hasApiKey` stay (compat) and delegate to the same code.
- Secrets never leave `safeStorage` (`*.key`); `keysSet` validates per-provider format; logs and errors never include the value; tests assert no IPC response or thrown error contains the secret (property test over every handler with a sentinel key).
- `copilot.json` unchanged; Settings Copilot page imports the existing page components.

New (renderer/components/settings/): `SettingsShell` (nav+search+page host), `SettingsNav`, `SettingsSearch`, `settings-registry.ts`, `SettingChip`, `ReadinessBadge`, `SaveState`, `UndoToast` helper (`showToast` + action — extend `ToastHost` with optional `action`), `KeyRow`/`KeyManager`, `TestResult`, `DangerZone`, `FocusPulse` hook. Reused: `Group/Row/Note` (move from `components/copilot/Group.tsx` to `components/kit/` and re-export), `ToggleSwitch`, `SegTabs`, `integrations/*`, `LocalModelSetup`, `ui/{tabs,scroll-area,alert-dialog,command,popover,input,select,slider,badge,progress}`. **No new shadcn components or npm dependencies.**

## 8. Data-migration risks

1. `settings.json` rewrite — mitigated by additive fields, atomic write, `.bak`. Test with fixture of v0.1.1 file.
2. `careerloom.refreshInterval`/`theme` localStorage values keep their keys (no migration).
3. `careerloom.section = integrations` → remap at read.
4. Copilot tab removal: `careerloom.copilot.selection` and pending-page slot may point at removed pages → fallback to `setup`.
5. Keys: no file moves, no re-encryption; `keysSet` writes the same `<name>.key` files. Plugin keys untouched.
6. Retention prune is opt-in (default: keep forever) so upgrading never deletes data.
