## Observations that shape the design (INFERENCE from the above)
1. **Practice is already "AI interviewer lite"**: runner emits interviewer lines through the same sink the live STT uses, so the overlay's cues + response suggestions work unchanged. The new work is *what to ask* (KB) and *how it's delivered* (TTS + voice answer), not overlay plumbing.
2. **No search, no DB, no TTS exist.** Each is a new, small, swappable adapter; none needs a native dependency if we choose `fetch` search APIs, JSON+BM25 (or `node:sqlite`), and OS `say`/cloud TTS.
3. **Research reuses `launchTask`** (progress UI, cancel, history for free) and Firecrawl/CDP for fetch; extraction/classification via the cheap `helper` tier.
4. **Prompt-prefix budget is the binding constraint for live retrieval**: 6000-token cap, cv already trimmed first. KB injection must be small (≈ 600–900 tokens) and ordered after stable sections so the cacheable prefix stays stable; per-question items go in the *user* turn, not the prefix.
