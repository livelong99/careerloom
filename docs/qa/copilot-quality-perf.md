## Harness: `scripts/copilot-eval/`

```
node scripts/copilot-eval/run.mjs                      # fake provider, all 70 questions
node scripts/copilot-eval/run.mjs --mode leak          # defective fake: the matching check must fail
OPENROUTER_API_KEY=… node scripts/copilot-eval/run.mjs --provider openrouter \
  --models openai/gpt-4.1-nano,anthropic/claude-haiku-4.5 --max-usd 0.30 --out /tmp/eval.json
```

- Goes through the real `buildPrompt` → engine → `parseSuggestion` → `guardSuggestion` path (`turn.ts`), with the provider wrapped to record raw text and first-token / total time per request.
- Live mode refuses `:free` models, sends `data_collection: deny`, runs one request at a time, stops at `--max-usd` (default 0.30), never prints the key.
- `questions.json` is generated by `gen-questions.mjs` (70 rows): behavioural 10, coding 8, system design 6, data eng 6, ML 6, cloud 6, product 4, HR/salary 6, trick/odd/illegal/unknown 10, follow-ups that depend on the previous answer 8. Candidate = `electron/copilot/fixtures/harness-cv.md`.
- Seven deterministic checks per answer: **format** (starts with `[SAY]`, order, bullet count, STAR only for behavioural), **length** (headline ≤15 words +3 grace, bullets ≤12 +3, ≤170 words, ≤30 code lines, brief/decline ≤60-70), **register** (no markdown/emoji/filler opener/AI self-reference/hedging), **claims** (guard flags + any number or capitalised name in a claim line that is not in the résumé, question or earlier turns), **rubric** (domain keyword groups), **leak** (text before `[SAY]`, `<think>`, "the user is asking", rule/marker mentions), **behaviour** (admits an experience gap, asks/states an assumption, rejects a false premise, declines improper asks, no forbidden claim).
- Fake-provider results (this proves the harness, not the prompt): `good` 70/70 pass; each defect mode fails its target check on all 70 (a few also trip a neighbouring check, e.g. `noformat` also fails leak) (`noformat`→format, `long`→length, `markdown`→register, `invent`→claims, `leak`→leak, `wrong`→rubric).

## Defects found and fixed

| # | Where | Problem | Fix | Test |
|---|---|---|---|---|
| 1 | `electron/ats/factCheck.ts` NAME regex (outside scope; shared with résumé Apply, 1-line regex) | `.` was allowed anywhere in a name, so a true name that ends a sentence ("…Fabrikam.") became "Fabrikam." and, worse, ran into the next sentence ("Northwind. My"). The guard then flagged a truthful answer as an invented employer | a dot only counts inside a name ("Node.js") | `guard.test.ts` "does not flag a true name that ends a sentence" |
| 2 | `guard.ts` PERSONAL | any `NN%` line was treated as a personal claim, so system-design answers ("aim for 99.9% availability", "alert at 80% disk") got `unsupported-number` flags | % is a claim only with an outcome verb ("cut costs by 75%"); money figures and first person still always count | `guard.test.ts` "does not flag percentages that are targets…" |
| 3 | `prompts.ts` coding spec | rule 5 said "code in a fenced block" but the format only has a one-sentence SAY and bullets: no place for code | coding questions get an explicit line: fenced block (≤25 lines) inside `[SAY]` after the headline, bullets = complexity/edge cases | `prompts.test.ts` |
| 4 | `prompts.ts` SYSTEM_RULES | gaps: no rule for hedging / "it depends" openers, markdown or emoji in spoken text, unknown term (bluffing), false premise (employer not on the résumé), protected-class questions, illegal/unethical asks, salary, clarifying, follow-up consistency, a hard length cap, "begin with `[SAY]`" | rules 2, 4, 6, 7 rewritten (net +~230 tokens in the cached prefix) | `prompts.test.ts` "SYSTEM_RULES coverage" |
| 5 | `recommended-models.json` fast tier | fast tier order was nano → luna → qwen: the first fallback is the same vendor as the default, so an OpenAI incident costs two failed attempts (each up to the 15 s first-byte timeout) before a different vendor is tried | order is now nano → qwen → luna; balanced and deep were already cross-vendor | `recommended-models.test.ts` |

## Model defaults and failover (recommendations; unmeasured)

Real data available: the user's `copilot/latency.jsonl` (46 turns, 2026-10-01 → 10-05, config = `nvidia/nemotron-3.5-lightning:free` on all three tiers): connect p50 1.08 s / p95 1.62 s, first token p50 1.29 s / p95 **8.05 s**, total p50 2.25 s / p95 **6.54 s**, prompt ~2.7k tokens, cache hit 0 on most turns.

1. The configured model is a **free** one: the p95 tail (8 s to first token) is the interview-killer. Move all tiers to paid defaults; per-answer cost is tiny (≈2.7k in + ≤420 out: gpt-4.1-nano ≈ $0.0004, haiku-4.5 ≈ $0.005).
2. Fastest reliable paid default to try first: `openai/gpt-4.1-nano` for the fast tier, `anthropic/claude-haiku-4.5` for balanced (explicit cache_control on the prefix, strongest answers of the cheap models). I did not measure them; confirm with the harness before changing the shipped default tier (`balanced`), since accuracy (rubric pass rate) is the other half of the trade-off.
3. Failover worst case is 3 attempts × 15 s first-byte timeout + backoff ≈ 45 s before a user sees nothing. Recommend (engine owner, `providers/openrouter.ts`): first-byte timeout ≈ 6 s for paid models when a fallback exists. Not changed here: out of my edit scope.
4. `retryable` only covers rate_limit / timeout / server. `model_unavailable` (a 404 for one model) is not retried; the engine only offers a suggestion. For a live interview an automatic same-tier fallback before any text appears would be safer. Engine-owner decision.
